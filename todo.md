- [ ] Resuming a previous check-in ("Fortsätt där jag var") switches the connection to the older session B via `overrideSession` and deletes the freshly-scanned session A (`deduplicateSession.ts` `doResume`). But the kiosk's WebSocket JWT still encodes A, and the client re-sends it on every reconnect (`SocketLoader.tsx`). After a reconnect (network blip / heartbeat timeout) the backend gets A's token → A no longer exists → `auth:status: session_not_found` and the kiosk breaks instead of landing back on B. Fix: on `overrideSession`, mint a fresh token for the new session and push it to the client (e.g. a new `session:token` WS message) so the client updates its stored `credentialsRef` token and reconnects authenticate as B. Two-sided (backend message + frontend handler). Surfaced alongside the 2026-07-20 fix for the navigation-stuck-after-resume bug (that one — connection not re-registered under the new session id in the broadcast registry — is fixed).
- [ ] No startup validation of step `with` config against each step's declared `inputs` schema. `evaluatedInputs` is just `stepDef.with` passed through (`step.ts`) and each step casts `ctx.getInputs() as typeof Inputs.infer` — the ArkType `inputs` schema is only used for the `.infer` type, never run. So all misconfig (missing required inputs, wrong types, unimplemented combos like `scoutnet:complianceGate`'s `mode: multiple` + `block: true`, or the required `message` in `mode: multiple`) fails late, at check-in time inside `onStepStart`, instead of at config load. Add a config-load pass that walks every step's `with` through its `inputs` schema (and ideally lets steps declare cross-field/semantic constraints) so a bad config is caught on boot. Surfaced by the 2026-07-20 compliance-gate code review.
